# ОБЪЕКТ №4 — сайт хоррор-квеста в Рудном

Премиальный одностраничный сайт для компании **«Объект №4»** (`object.rdn`) — хоррор-квеста
в Рудном, Костанайская область.

Стек: **Next.js (App Router) · TypeScript · Tailwind CSS 4 · Motion-ready CSS animations · Lucide-free
inline SVG иконки**. Никаких лишних зависимостей: в `package.json` только `next`, `react`,
`react-dom`, `motion`, `lucide-react`, `clsx` — все анимации построены на CSS + одном
`IntersectionObserver`.

---

## Быстрый старт

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production-сборка
npm run start    # запуск собранного приложения
```

Перед деплоем скопируйте `.env.example` в `.env.local` и заполните переменные.

---

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Публичный адрес сайта. Используется в `canonical`, Open Graph, `robots.txt` и `sitemap.xml`. Если не задан — подставляется `http://localhost:3000`. |
| `BOOKING_WEBHOOK_URL` | Куда пересылать заявки с формы (Telegram Bot API, CRM, Make/Zapier, свой обработчик). |
| `BOOKING_WEBHOOK_CHAT_ID` | Необязательный chat id для Telegram-бота. |

### Подключение заявок

Форма уже отправляет `POST /api/booking` с полями `name`, `phone`, `comment`. Чтобы заявки
начали приходить, достаточно задать `BOOKING_WEBHOOK_URL` — код менять не нужно
(`app/api/booking/route.ts`). Если URL не задан:

* заявка валидируется и логируется на сервере;
* на клиенте показывается кнопка WhatsApp с уже подставленными данными — лид не теряется.

### Фотографии

В `_source_photos/` лежат исходники, скачанные из фотоальбома 2ГИС. В `public/media/v2/` — уже
прогнанные через `_tools/build-media.py` варианты:

* водяной знак «2GIS» снимается обрезкой до любой художественной кадрировки — на снимках,
  которые попали на сайт, его нет;
* у каждого кадра свой набор анкоров кадрирования: широкий кроп оставляет полную ширину и режет
  высоту, поэтому вертикальное кадрирование и определяет, выживет ли сюжет;
* единый грейд (насыщенность −22 %, контраст +14 %, яркость −10 %) — кадры читаются как одна
  мрачная серия;
* WebP, три ширины на каждый кадр, общий вес ≈ 2,1 МБ на весь сайт;
* доминирующий цвет каждого кадра используется как фон-заглушка → нет белой вспышки и сдвига
  вёрстки (CLS = 0).

Из пяти кандидатов в галерею попали четыре: `g12_angelina` (коридор) исключён — примерно треть
любого возможного кропа этого кадра абсолютно чёрная и в сетке читалась как дыра.

**Почему путь версионирован (`/media/v2/`).** Каталог `/media/*` отдаётся с
`Cache-Control: immutable`, поэтому перезапись файла под тем же именем оставляет старые байты
в кэше браузеров и на границе CDN. Именно так исправленный водяной знак продолжал показываться
на уже задеплоенном сайте. При любом изменении пайплайна поднимите `MEDIA_VERSION` в
`_tools/build-media.py`.

## Структура

```
app/
  layout.tsx          шрифты, метаданные, LocalBusiness JSON-LD, шапка/подвал
  page.tsx            композиция секций + FAQPage JSON-LD
  globals.css         дизайн-токены, анимации, prefers-reduced-motion
  icon.svg            фавикон
  apple-icon.png      иконка iOS
  robots.ts sitemap.ts
  api/booking/route.ts
components/           секции и переиспользуемые блоки
lib/site.ts           все реальные данные компании (единственный источник правды)
lib/media.ts          манифест изображений
_tools/               скрипты обработки изображений и генерации бренд-ассетов
```

Скрипты в `_tools/` не входят в сборку и запускаются вручную:

```bash
python _tools/build-media.py        # WebP-варианты из исходников -> public/media/v2
node   _tools/gen-media-ts.mjs      # перегенерирует lib/media.ts из манифеста
python _tools/build-brand.py        # public/og.png и app/apple-icon.png
python _tools/contact-sheet-final.py  # контактный лист итоговых кадров (визуальный контроль)
```

`lib/media.ts` **генерируется** — не редактируйте его руками, иначе `width`/`height` в разметке
разъедутся с реальными файлами и вернётся сдвиг вёрстки. Порядок всегда такой:
`build-media.py` → `gen-media-ts.mjs`.

### Оформление

* Тема только тёмная: секции разделяются не яркостью, а значением поверхности
  (`#050506` → `#0b0b0d` → `#16151a` → `#1e1c22`).
* Заголовки — **Playfair Display** (высококонтрастная антиква с полной кириллицей), интерфейс и
  таблицы цен — **Inter** с табличными цифрами. Больше двух семейств не используется.
* Мелкий акцентный текст идёт в тоне `ember` (`#ff6a4d`), а не в основном `signal` (`#d53820`):
  последний на почти чёрном даёт ≈3,5:1 и не проходит AA для мелкого кегля.

## Доступность и производительность

* `prefers-reduced-motion` полностью отключает reveal-анимации, тикер и плавный скролл;
* у всех изображений заданы `width`/`height` и фон-заглушка → CLS = 0;
* вторичный текст поднят до значений, проходящих WCAG AA (≥4,5:1) на тёмных поверхностях —
  проверено расчётом контраста, а не на глаз;
* hero-изображение — единственное с `fetchpriority="high"`, остальные `loading="lazy"`;
* фокус-состояния `:focus-visible`, skip-link, `aria-*` на меню, аккордеоне, лайтбоксе и
  переключателе локаций; honeypot в форме;
* карта подключена как lazy-iframe OpenStreetMap по точным координатам — без API-ключей и
  сторонних трекеров. Подложка под картой оформлена, поэтому блок не выглядит пустым, пока
  тайлы грузятся; навигация всё равно ведёт в 2ГИС.
